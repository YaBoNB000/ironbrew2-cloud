# IronBrew2

VM-based Lua 5.1 bytecode obfuscation with Luau/Roblox-aware runtime defenses.

## Build and run

Requirements:

- .NET 8 SDK
- Lua 5.1 and `luac` 5.1 in `PATH`

```bash
dotnet build "IronBrew2 CLI/IronBrew2 CLI.csproj" -c Release
dotnet "IronBrew2 CLI/bin/Release/net8.0/IronBrew2 CLI.dll" input.lua
```

The CLI has one supported configuration. Control-flow processing, bounded IR-native SuperOperators, DEFLATE, VM-integrated AntiDump and strict `EnvironmentLock` executor attestation are enabled. Mutation, mega operators and destructive executor hooks remain disabled. Use `--line-info` only when original-line error reporting is required.

Generated scripts are executor-only by default. Admission is brand-neutral: `identifyexecutor()` must be stable and non-empty, but no executor name or version is compared with an allow-list. Every required contract is a hard AND, including Roblox host behavior, stable `getgenv()`, `checkcaller()`, C/L closure classification, `newcclosure`, `loadstring`, debug constant/upvalue/prototype/setupvalue behavior, native primitive provenance, primitive snapshots and a randomized behavioral transcript. Plain Lua/Luau, Roblox Studio, incomplete shims and any environment that changes after startup do not execute the payload.

Successful attestation currently restores a compatibility scalar as `transcript + Build-local offset` (the expected token literal and direct equality check are not shipped), then payload derivation expands it with the salt into four coupled binding words. Independent folds produce the envelope stream seed, outer-integrity key and `GuardPayloadBinding`; the latter binds chunk/instruction/opcode state, initial flow state, route token, transition keys, block verifiers and block manifests. The guard runs at VM startup, after root deserialization, before first-block entry and periodically during dispatch. Failure is sticky: invocation-local plaintext references are cleared where available, then the current thread enters a randomized, non-yielding bit-mixing state graph that never returns and uses fixed O(1) memory. It prints and throws no detection message and performs no network/file probes or background scans. The one intentional global mutation is the configured output/error policy described below. An external watchdog may still terminate the busy thread.

This is a client-side cost amplifier, not an unforgeable executor oracle. A sufficiently capable environment can simulate all contracts or patch the shipped guard and token derivation.

Primitive bootstrap supports proxy-backed executor thread environments. Standard roots such as `rawget`, `string`, `table`, `math`, `debug`, and `pcall` are resolved with raw-first/indexed-fallback lookup; member lookup rejects a nil parent instead of calling `rawget(nil, key)`. Guard snapshots use the same raw/indexed model, and VM environment reads fall back to indexed access when a raw slot is absent.

Every generated `CALL` and `TAILCALL` handler also passes its callee through a per-call dynamic-loader validator. When the callee is the captured `loadstring`, the validator re-reads the current environment binding, checks identity and C-closure provenance, builds a state/call-count-dependent `return <number>` challenge from character codes, compiles and executes it, and verifies the loaded closure's constant table before invoking the requested loader call. This detects both post-startup rebinding and many in-place behavior hooks; distinct attacker wrappers still require broader call-graph analysis and are not claimed to be impossible.

After successful root verification and before protected execution, the runtime permanently installs one shared no-op function as `print`, `error`, and `warn` in the thread environment, `_G`, and a distinct `getgenv()` table (aliases are identity-deduplicated). The keys are assembled from character codes and all installer identifiers are build-randomized. The final thread-level `getfenv()` call is protected with `pcall`; if an executor returns `nil` or a non-table at that late call depth, installation and `Wrap` fall back to the already captured `PrimitiveEnvironment`, so `rawget(nil, ...)` cannot occur. This deliberately changes payload semantics: explicit calls to those three globals return `nil` and produce no output/error. VM-internal integrity faults and `--line-info` reporting retain captured private error paths and are not routed through the disabled payload binding.

Generated files use the v5 protected payload with feature value `15`. After the real serialized body is DEFLATE-compressed, it is state-masked, split into records, and interleaved with 64–96 KiB of independent CSPRNG entropy records. An entropy digest participates in the inner body-mask state, while a separate envelope tag authenticates framing and physical record order before inflate; deleting, modifying, or reordering a record is rejected even if the outer payload tag is recomputed. The v5 outer tag replaces v4's reversible polynomial seed prefix with a two-lane, cross-coupled authenticator and uses a separately derived integrity key: public ciphertext and the tag can no longer be walked backwards in O(n) to recover the environment-derived envelope stream seed. This remains client-side protection rather than a server-held secret.

V5 authenticates every complete prototype slice before parsing its schema or child framing. Constants remain independently masked and tagged opaque capsules at startup. A complete block manifest binds its range, route token, ordered constant references and referenced capsule bytes, flow verifier, ordered successor/state records, and instruction body. Each block body is a five-page columnar IR: descriptor, opcode, A, B and C streams are independently length-framed and physically reordered by a non-identity permutation derived from that block's execution state and prototype keys. The runtime authenticates the manifest before recovering page roles and rejects any framing mismatch, invalid descriptor, or under/over-consumed column. Referenced capsules remain unopened after record decoding: each constant operand is a lazy proxy field and its capsule is authenticated and decoded only when the selected handler first indexes that operand. With AntiDump enabled, plaintext constants and instructions therefore exist only during the current invocation's handler-use window; the shared prototype instruction table remains empty and its constant store contains only opaque capsules.

Each generation independently permutes the logical ABI of all 16 `Chunk`, 10 `Block`, 4 `Flow`, and 7 `FlowCache` slots. Chunk and Block records are additionally prototype-local proxies: each proxy maps the build-wide numeric ABI into a second K1/K2/K3-derived storage permutation, with prototype length or block start/verifier separating instances. Instruction columns use one of four decoder families selected independently from each prototype's keys; physical column framing remains authenticated while byte order/masking differs across prototypes. A non-sequential transfer replaces the invocation-local cache and a later re-entry reauthenticates and decodes the opaque body and its referenced capsules. Top-level instruction fetch carries opcode/A/B/C, lazy constant metadata and any fused operand bundle through prototype-keyed Flow overlay slots, dispatches four prototype-selected synthetic materializer stages, rewinds PC/Flow four times, and constructs a use-point operand proxy only on the final replay. Safe straight-line IR sequences are physically lowered to one authenticated record with a combined member descriptor; fusion excludes CFG, CLOSURE/CLOSE/upvalue, SETLIST/data-word and unsafe variable-return boundaries, and its handler consumes supplemental operands without replaying `GetInstruction`. All members share one generated register dataflow proxy: writes remain immediately visible in the real VM stack, while unchanged cross-member reads are forwarded through a nil-safe invocation-local cache and externally changed values invalidate that cache. Base91 segments are consumed incrementally without constructing one encoded string; decoded ciphertext is retained as bounded 2 KiB chunks behind a byte accessor. Common register writes choose among six dataflow lowerings, including captured `RawSet`, while stack/global reads independently mix indexed access with captured `RawGet`. Terminal leaves also compose shared stack/environment acquisition, binary/unary operation, destination/writeback and PC-transition fragments selected by build-random tokens; build logs and the randomized matrix verify all forms are exercised. The envelope increases each generated payload by 64–96 KiB before basE91 expansion; this is an intentional fixed protection/size tradeoff, not removable padding.

Multi-block prototypes are selected automatically for dispatcher flattening only after conservative CFG, jump-companion, `SETLIST C==0`, and Closure-binding checks. Unsupported or malformed shapes fall back atomically to the protected real-PC path without partial dispatcher metadata; no source marker is required.

The source frontend and build pipeline still consume Lua 5.1 bytecode. Luau/Roblox priority in this release applies to strict runtime executor attestation; Luau-only source syntax still requires a future native frontend.

## Hardening and tests

- Implementation plan: [`HARDENING_PLAN.md`](HARDENING_PLAN.md)
- Implementation/test report: [`HARDENING_REPORT.md`](HARDENING_REPORT.md)
- Anti-dump summary: [`反dump优化总结.md`](反dump优化总结.md)
- Final-output attack baseline: [`docs/static-attack-baseline.md`](docs/static-attack-baseline.md). The current expected result is intentionally a successful static recovery of carrier order, environment binding, complete prototype metadata, all constant capsules (`9` for the tracked `test.lua`), physical/fused logical instruction widths and canonical head-opcode IDs; each subsequent hardening milestone must reduce this measured recovery rather than merely break the test parser.
- Linux differential suite: [`tests/run_linux_tests.sh`](tests/run_linux_tests.sh). Set `IB2_RANDOM_RUNS=20` for the full randomized matrix; it verifies removal of the v4 polynomial outer-seed inverse, the 64–96 KiB entropy envelope, outer-tag-valid record tamper rejection, v5 prototype/block/capsule authentication, per-block non-identity column-role maps and authenticated column framing/consumption rejection, all four non-identity runtime slot layouts and cross-build ABI variation, all four guard checkpoints, ephemeral block/constant-cache behavior, dispatcher selection/fallback, flow tamper rejection, Closure/CLOSE/SETLIST/variable-return fusion boundaries, use-point constants, shared handler fragments, physical IR fusion, and Lua 5.1 semantics. Positive semantic tests run through [`tests/executor_runner.lua`](tests/executor_runner.lua)'s trusted executor contract; plain and malformed environments are launched under an external timeout and must stay silent and non-returning.
- CI: [`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs the full Linux suite and Release publish builds for Linux x64, Windows x64, and macOS arm64.
